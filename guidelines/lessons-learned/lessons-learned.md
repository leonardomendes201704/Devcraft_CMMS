# Lessons Learned

| ID | Date | Context | Problem | Root Cause | Fix | Preventive Action | Status |
|---|---|---|---|---|---|---|---|
| LL-001 | 2026-04-17 | Tooling | `dotnet new sln` generated `.slnx` and broke scripted `dotnet sln ... .sln add` | SDK behavior changed in .NET 10 CLI | Use `Devcraft_CMMS.slnx` in all commands | Keep command catalog updated with `.slnx` references | prevented |
| LL-002 | 2026-04-17 | Tooling | `npm` PowerShell shim blocked by execution policy | Script execution policy in host | Use `npm.cmd` explicitly in PowerShell | Add this to command guidelines for Windows | prevented |
| LL-003 | 2026-04-17 | Backend/API | `POST /api/tasks` retornava 500 com DataAnnotations em requests | Uso de `record` + metadata de validacao em propriedade primaria | Migrar DTOs de request para classes com propriedades `init` | Evitar `record` para requests com DataAnnotations no ASP.NET Core | prevented |
| LL-004 | 2026-04-17 | Backend/API | `POST /api/tasks` retornava 500 no `CreatedAtAction` | Rota alvo nao existia para `{id}` | Retornar `Created(\"/api/tasks/{id}\", body)` | Validar retorno de create com smoke test HTTP real | prevented |
| LL-005 | 2026-04-17 | Testing/Playwright | Execucoes Playwright conflitaram porta 5270 | Rodar suites concorrentes que sobem mesmos web servers | Executar Playwright de forma sequencial por suite/projeto | Nao paralelizar comandos que compartilham portas locais | prevented |
| LL-006 | 2026-04-17 | Governance/Workflow | Commits bloqueados repetidamente por falta de update no `CHANGELOG.md` | Changelog estava sendo atualizado apenas no fim, depois da tentativa de commit | Adicionar preflight de changelog no fluxo (`bash scripts/check-changelog.sh --working-tree`) antes de stage/commit | Padronizar sequencia obrigatoria: atualizar changelog primeiro, depois validar, depois commitar | prevented |
| LL-007 | 2026-04-17 | Governance/Task-First | Alteracao "Shorten menu labels" foi implementada antes de criar task no Kanban e sem registrar start/end/spentHours | Agente nao tinha carregado `AGENT.md` + `workflows/task-lifecycle-directive.md` como contexto antes de executar | Regularizacao retroativa com task `0a6124e6-2353-46a9-99b4-1cc3f1a47c2f` + Playwright regression spec `shell-menu-labels.spec.ts` + board.md atualizado | Toda solicitacao de chat: triagem -> criar task -> start local -> active -> implementar -> resolved -> spentHours -> close. Nunca pular o passo da task, mesmo para mudancas pequenas. | prevented |
| LL-008 | 2026-04-17 | Tooling/Windows | `bash scripts/check-changelog.sh` falha no PowerShell com `WSL ... execvpe(/bin/bash) failed` | WSL instalada mas sem distribuicao padrao; `bash` no PATH aponta para shim do WSL | Usar caminho completo do Git bash: `"C:\Program Files\Git\bin\bash.exe" scripts/check-changelog.sh --working-tree` | Adicionar wrapper PowerShell (`scripts/check-changelog.ps1`) ou documentar caminho explicito de `bash.exe` no catalogo de comandos | prevented |
| LL-009 | 2026-04-17 | Frontend/Evidence | Imagens de evidencia recem-adicionadas apareciam como "Image unavailable" no modal do Kanban mesmo com o arquivo existente em `public/evidences/` | Vite dev server rodando no container `devcraft_cmms_web` nao descobre arquivos criados em `public/` apos o startup: requisicao cai no fallback SPA e retorna `text/html 615b` ao inves do PNG | Reiniciar `devcraft_cmms_web` apos gerar novas evidencias (`docker restart devcraft_cmms_web` ~6s) | Skill `.cursor/skills/devcraft-task-lifecycle/` dispara o restart automaticamente no `close` quando ha evidencia de imagem; Playwright/CLI de task sempre rodam via skill; para o longo prazo avaliar servir evidencias pelo backend (UseStaticFiles) ou usar watcher custom | mitigated |
| LL-010 | 2026-04-17 | Tooling/PowerShell | `powershell -File script.ps1 ... -PayloadJson '{...}'` passava JSON corrompido para o script, gerando HTTP 400 `PayloadJson must contain valid JSON` | Subprocess `powershell.exe` reparseia argumentos: chaves e aspas dentro de JSON literal sao despojadas antes de chegar ao `$args` do script | Invocar scripts com o call operator (`&`) na mesma sessao: `& scripts/task.ps1 evidence -PayloadJson '{...}'` | Documentar na skill `devcraft-task-lifecycle` (SKILL.md) que invocacao canonica e via `&`, nunca `powershell -File`, para qualquer comando que aceite payload JSON | prevented |
